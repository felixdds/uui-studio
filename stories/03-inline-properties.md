# 一个属性旁边的小叉

UUI Studio 的属性编辑器里，一个属性旁边可能出现恢复默认的小叉。它很不起眼，却能说明 UDM 的一个核心选择：除了值是什么，还要知道用户有没有明确设置它。

## 先说 UDM

UDM 是 Unified Document Model，也就是统一文档模型。它用一套应用描述规则组织组件、属性、布局、事件、状态和相关行为，再由构建与运行系统转换为 DOM、CSS 和 JavaScript，通过 WebView 渲染。Rust 承担宿主、构建和相关平台能力。

我希望利用成熟的技术，同时让设计器、属性编辑器和运行时遵守一致的模型。其中一条原则是：

> 能推导出来的，就不重复定义。

另一条同样重要：用户明确作出的决定，必须得到尊重。

## 两个相同的显示值

假设属性编辑器显示 `inherited`，可能有两种情况：用户没有明确设置这个属性，系统按照默认或继承规则得到了这个值；也可能是用户明确把它设置为 `inherited`。

显示值相同，用户意图却不同。后者存在一项明确设置，所以旁边仍然可以有恢复默认的小叉。

UUI Studio 的 Form 文件通过 inline 属性保存显式设置。属性的值说明设置了什么，而对应属性是否存在，说明用户有没有明确指定。这里不需要再保存一份 `isDefault` 或 `isExplicit` 状态。

| 情况 | inline 设置 | 点击重置的含义 |
| --- | --- | --- |
| 未明确设置 | 不存在对应属性 | 已由默认和继承规则计算 |
| 明确设置为 inherited | 存在对应属性 | 删除这项显式设置，重新计算 |
| 明确设置其他值 | 存在对应属性 | 删除这项显式设置，重新计算 |

这个表描述的是语义，不是新增的代码接口。

## 重置不是再写一个默认值

点击小叉时，Studio 删除对应的 inline 属性，让系统重新按照默认和继承规则计算。它不需要猜测用户是不是曾经改过，也不需要把当时的默认值重新写进 Form。

对我来说，减少重复定义的意义在于减少需要维护的关系，以及这些关系将来出现不一致的机会。同时，用户明确设置的东西不能因为它恰好等于当前默认值，就被当成没有设置。

一个小叉，背后其实是模型怎样理解用户意图。
