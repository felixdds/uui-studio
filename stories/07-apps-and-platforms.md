# 为了一个 BMI 计算器 我先做了一套平台

我经常开玩笑：“为了开发一个 BMI 计算器，我先开发了一套跨平台应用开发平台。”

BMI Calculator 和 MyBible，是我用 UUI Studio 开发的应用。对我来说，它们不仅是展示材料，也是发现平台哪里不好用的机会。

## 应用把问题带回来

BMI 计算器让界面与交互有了具体任务；MyBible 则带来 SQLite 数据、内容导航、搜索和资源打包等需求。把应用真正做出来，才能看到 UDM 在实际使用中的表现。

但一个人的需求和时间总是有限。只做我自己的几个应用，不足以覆盖开发平台可能遇到的所有场景。这也是我希望寻找合作伙伴、引入更多真实项目的原因。

## 从 Python 探索到 Rust

UUI Studio 最初曾用 Python 实现部分功能。后来，为了改善交付方式和工程结构，我开始考虑迁移到 Rust。

我不懂 Rust，于是先让 Codex 做小规模实验，再逐步扩大迁移范围。有一次重要迁移持续了两个多小时，重新构建并运行成功。

过去，想使用一种不熟悉的语言完成这样的工作，往往得先投入很多时间学习。现在，我可以提出架构目标，让 AI 处理实现，再通过实际结果来判断。

Rust 在这里是实现工具。最终我关心的仍是，它是否适合系统要解决的问题。

## 当时要证明的是跨平台编译

我们先后在 Windows、Android、Linux、macOS 和 iOS 上成功编译。换平台编译没有遇到难以克服的障碍，之后就回到 Windows 继续开发。

这个阶段，我需要证明的是：这套代码能够跨平台编译。并没有要求当时就完成各平台全部功能和设备的验收。

历史上的编译经历，与当前公开版本在某个平台上完成了哪些检查，是两件需要分开说明的事。构建成功、启动成功、功能检查和长期稳定性，也不应合并成一个结论。当前公开测试包的范围，请以仓库的[验证说明](../README.md#当前验证范围)为准。

## 先继续完善已有能力

跨平台方向有了阶段性依据，我就把精力放回 Windows 上的日常开发，继续完善共同的组件、规则和体验。

一套平台不必永远通过增加功能证明价值。让已有的东西更一致、更可靠、更容易使用，同样是实实在在的进展。
